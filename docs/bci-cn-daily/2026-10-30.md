*eeglab2mne: Translate EEGLAB Scripts to MNE-Python and Grade Which Steps You Can Trust*

**简介：** 新建仓库 eeglab2mne（2026-10-29）解决实验室迁移的真实痛点：读入 EEGLAB 脚本**或 `.set` 文件里的 `EEG.history`**，产出等价 MNE-Python 脚本，并给出**逐步骤评级的迁移报告**（exact / approximate / 不支持）。它把「静默差异」直接点名：基线以毫秒而非秒给出、**1-based 组件编号**、幅度阈值被当成峰峰值阈值、以及 ICA 组件编号在重新拟合后不再有意义——这些正是手工改写时最容易漏、又最难在结果里发现的地方。仓库有 CI 测试与规范结构。对正在从 MATLAB/EEGLAB 迁到 Python 的团队，这比逐行手译可靠得多；但请把报告里的 approximate 视为**必须人工复核**的清单。

**Brief:** Created 2026-10-29, eeglab2mne reads an EEGLAB script or the EEG.history inside a .set file, writes an equivalent MNE-Python script, and grades each migrated step (exact, approximate). It names the silent differences: baselines in milliseconds rather than seconds, 1-based component numbers, amplitude thresholds turning peak-to-peak, and ICA component numbers losing meaning after refitting.

- It takes an EEGLAB script or the EEG.history inside a .set file, emits an equivalent MNE-Python script, and produces a migration report grading each step (exact, approximate, …).

**Brief:** braindecode merged #1497 fixing DuIN when a checkpoint is loaded at an n_times different from training: the head now keeps its initial input length instead of being skewed by the new window length. Such bugs are the worst kind — weights load and shapes match, but semantics drift with no error, so models misbehave at the new window length. Verify outputs across both n_times after upgrading.

- #1497 让 **DuIN** 在 `n_times` 与训练时不同时也能正确加载 checkpoint——头部保持其原始输入长度，而不是被新窗口长度带偏。

- 对用预训练 DuIN 做迁移或改变窗口长度的团队，建议升级后对比同权重在两种 n_times 下的输出一致性。

- #1497 lets DuIN load a checkpoint when n_times differs from training time, with the head keeping its initial input length instead of being skewed by the new window length.
- This class of bug is nasty: weights load, shapes match, but semantics drift — no error, only odd behaviour at the new window length.
- Teams transferring pretrained DuIN or changing window length should compare outputs across both n_times after upgrading.

### [pyRiemann 修 Kmeans：不再被 sklearn 当分类器，inertia/score 语义对齐](https://github.com/pyRiemann/pyRiemann/pull/513)
*pyRiemann Fixes Kmeans: No Longer Seen as a Classifier, inertia and score Aligned*

**简介：** pyRiemann 合并 #513，修 `Kmeans` 被 scikit-learn **当成分类器**的问题——起因是接口/基类不匹配，结果在 `Pipeline`、交叉验证与 `GridSearch` 里会被按分类器对待，行为与预期不符。同时把语义对齐 sklearn：**`inertia` 改为距离平方和**，`score()` 返回与 inertia **相反方向**（越大越好）。这两处合起来意味着：如果你之前用 `inertia` 做肘部法选簇数、或依赖 `score()` 的符号排序，结论可能需要重算——尤其 `score()` 方向不一致时，调参会系统性地选反。建议升级后重跑聚类实验并显式检查 `get_params`/`score` 的语义。

**Brief:** pyRiemann merged #513 fixing Kmeans being treated as a classifier by scikit-learn because of an interface mismatch, which made Pipelines and cross-validation handle it wrongly. It also aligns sklearn semantics: inertia is now the sum of squared distances and score() returns the opposite direction. Anyone using inertia for elbow selection or score() ordering should re-run experiments.

- #513：`Kmeans` 之前被 scikit-learn 识别为**分类器**（因为它继承了错误的基类/接口），在 `Pipeline` 与交叉验证里会被错误对待。
- 同时对齐 sklearn 语义：**`inertia` 改为距离平方和**，`score()` 返回与 inertia 相反的方向（越大越好），避免调参时选反。
- 对把黎曼聚类塞进 sklearn 流水线或用 inertia 做肘部法选簇数的团队，这类语义修正会直接改结论。

- #513: Kmeans was being treated as a classifier by scikit-learn because it inherited the wrong interface, so Pipelines and cross-validation handled it incorrectly.
- It also aligns sklearn semantics: inertia is now the sum of squared distances, and score() returns the opposite direction (higher is better), so tuning no longer optimises the wrong sign.
- Teams plugging Riemannian clustering into sklearn pipelines or using inertia for elbow selection will see conclusions change.
