*EEG-FM-Benchmark Fixes a Boolean CLI Trap: Every One of 70 Reproduce Commands Had a Flipped Flag*

**简介：** EEG-FM-Benchmark 合并 #5，修一个非常典型的「能跑但结果不同」的坑：`run_finetuning.py` 的布尔开关用 **`type=bool`**，而 Python 把任何**非空字符串**都当 True，于是 **`--apply_EA False` 实际是开启 EA**。更严重的是影响面——`config/*.json` 里共 **70 条 `reproduce_command`**，走当前解析器时**每条都至少有一个 flag 与它写的值相反**。对基准仓库，这类 bug 直接动摇「别人能否复现我的数」：命令贴出去了、也能跑通，但实际配置不是你标称的那套。修复方式通常是改用 `store_true`/`store_false` 或显式解析字符串。建议所有提供 reproduce 命令的项目都自查一遍同类写法。

**Brief:** EEG-FM-Benchmark merged #5 fixing a textbook 'runs but differs' bug: boolean switches used type=bool, and Python treats any non-empty string as True, so --apply_EA False turned EA on. Worse, all 70 reproduce_command entries in config/*.json pass through that parser, each with at least one flag opposite to its value. Other projects should audit the same pattern.

- `run_finetuning.py` 的布尔开关用 `type=bool`，Python 把任何**非空字符串**都当 True，于是 `--apply_EA False` 实际**打开了 EA**。
- 影响不止用户手输：`config/*.json` 里的 **`reproduce_command` 共 70 条**，走当前解析器时**每条都至少有一个 flag 与预期不符**。
- 这是「复现命令跑得通、结果却不同」的典型成因；对基准仓库，它直接动摇结论可比性。

- Boolean switches in run_finetuning.py used type=bool, and Python treats any non-empty string as True, so --apply_EA False actually turned EA on.
- The impact goes beyond manual runs: all 70 reproduce_command entries in config/*.json go through the same parser and every one has at least one flag that does not match its value.
- This is a textbook cause of 'the reproduce command runs but results differ', and for a benchmark repo it undermines comparability outright.
